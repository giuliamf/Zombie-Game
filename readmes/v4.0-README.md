## Descrição do Projeto

Esta quarta entrega expande o projeto com a introdução de sistemas fundamentais para interatividade e controle temporal em jogos 2D. Foram implementados um gerenciador de entrada (InputManager), um sistema de tempo (Timer), controle de delta time e um sistema de câmera que permite movimentar o mundo.

O projeto agora permite interação por teclado, movimentação da câmera sobre o mapa e controle de comportamento dos objetos com base no tempo. O inimigo (zombie) possui animação, muda de estado após determinado intervalo de tempo e pode ser eliminado manualmente pelo jogador através de entrada de teclado.

A aplicação exibe uma janela de 1200x900 pixels com:
- plano de fundo
- mapa baseado em TileMap
- inimigo animado
- música ambiente
- movimentação de câmera com teclado

## Objetivos da Entrega 4

Os principais objetivos desta entrega são:

1. Implementar um sistema de entrada através da classe [`InputManager`](include/InputManager.h)
2. Utilizar delta time no game loop para garantir comportamento consistente independente de FPS
3. Criar a classe [`Timer`](include/Timer.h) para controle de tempo interno
4. Implementar um sistema de câmera com a classe [`Camera`](include/Camera.h)
5. Integrar entrada de teclado com a lógica do jogo
6. Controlar comportamento do inimigo com base em tempo e input
7. Garantir desacoplamento entre lógica, renderização e controle

## Arquitetura e Principais Classes

### Evolução da Arquitetura

A Entrega 4 mantém a arquitetura baseada em composição introduzida nas entregas anteriores e adiciona sistemas essenciais para interatividade e controle temporal. O projeto passa a integrar entrada de usuário, controle de tempo e movimentação de câmera ao fluxo principal do jogo.

### Game

A classe [`Game`](include/Game.h) continua responsável pelo controle da aplicação, agora incorporando entrada de dados no loop principal.

**Responsabilidades:**
- Inicializar e finalizar SDL2 e bibliotecas auxiliares
- Executar o game loop principal
- Calcular o delta time (`dt`)
- Atualizar o [`InputManager`](include/InputManager.h) a cada frame
- Fornecer acesso global à instância única

### InputManager

A classe [`InputManager`](include/InputManager.h) encapsula o gerenciamento de entrada do usuário.

**Responsabilidades:**
- Processar eventos SDL
- Armazenar estado das teclas
- Detectar pressionamento (`KeyPress`) e liberação (`KeyRelease`)
- Substituir o uso direto da SDL no restante do código

### Timer

```bash
Game::Run()
→ InputManager::Update()
→ State::Update(dt)
→ Camera::Update(dt)
→ Component::Update(dt)
→ Render com Camera aplicada
```

## Funcionamento Interativo

O jogador pode interagir com o jogo através do teclado.

### Controles

- **W** → mover câmera para cima  
- **S** → mover câmera para baixo  
- **A** → mover câmera para esquerda  
- **D** → mover câmera para direita  
- **ESPAÇO** → eliminar o zombie imediatamente  

---

## Comportamento do Zombie

O inimigo possui dois modos de morte:

### 1. Baseado em tempo

Após aproximadamente 3 segundos:
- o Timer atinge o limite
- o Animator é interrompido
- o sprite muda para o frame de morte

### 2. Baseado em input

Ao pressionar a tecla **ESPAÇO**:
- o zombie é eliminado imediatamente
- a animação é interrompida
- o frame final é aplicado
