## Descrição do Projeto

Esta segunda entrega expande a base estrutural desenvolvida na Entrega 1, implementando um sistema completo de GameObjects baseado em composição e um sistema de animação de sprites. O projeto mantém o foco em arquitetura de engine e orientação a objetos, estabelecendo fundações sólidas para futuras implementações de gameplay.

O programa exibe uma janela de 1200x900 pixels com música de fundo, um plano de fundo renderizado como GameObject e um inimigo (zombie) animado automaticamente através de um sprite sheet. A animação é controlada por delta time, garantindo consistência independente da taxa de quadros.

## Arquitetura e Principais Classes

### Padrão de Composição

O projeto utiliza o padrão de composição (Entity-Component System simplificado), onde GameObjects são entidades genéricas que ganham funcionalidades através da adição de Components especializados. Esta abordagem oferece flexibilidade e reutilização de código.

### Game (Singleton)

A classe `Game` mantém suas responsabilidades da Entrega 1 e adiciona o cálculo de delta time.

**Responsabilidades:**
- Inicializar e finalizar os subsistemas da SDL
- Criar e gerenciar a janela e o renderer
- Controlar o game loop principal
- Calcular o delta time (dt) para atualizações baseadas em tempo
- Fornecer acesso global através do padrão Singleton

**Métodos principais:**
- `GetInstance()`: Retorna a instância única da classe
- `Run()`: Executa o game loop com cálculo de dt
- `GetRenderer()`: Retorna o renderer SDL
- `GetState()`: Retorna o estado atual do jogo

### State

A classe `State` gerencia o ciclo de vida dos GameObjects, delegando a lógica e renderização para os próprios objetos.

**Responsabilidades:**
- Gerenciar a lista de GameObjects
- Carregar recursos iniciais (música)
- Propagar chamadas de Start(), Update() e Render() para todos os GameObjects
- Detectar solicitação de encerramento do programa

**Métodos principais:**
- `LoadAssets()`: Carrega recursos iniciais
- `Start()`: Inicializa todos os GameObjects
- `Update(float dt)`: Atualiza todos os GameObjects com delta time
- `Render()`: Renderiza todos os GameObjects
- `AddObject(GameObject* go)`: Adiciona um novo GameObject ao estado
- `QuitRequested()`: Indica se o usuário solicitou o encerramento

### GameObject

A classe `GameObject` representa uma entidade genérica do jogo. Sua funcionalidade é definida pelos Components que possui.

**Responsabilidades:**
- Armazenar posição e dimensões (através de Rect box)
- Gerenciar uma lista de Components
- Propagar chamadas de Start(), Update() e Render() para seus Components
- Garantir que Start() seja executado apenas uma vez

**Atributos principais:**
- `box`: Retângulo que define posição e dimensões
- `components`: Lista de componentes que definem o comportamento

**Métodos principais:**
- `AddComponent(Component* component)`: Adiciona um componente
- `Start()`: Inicializa todos os componentes (executado uma vez)
- `Update(float dt)`: Atualiza todos os componentes
- `Render()`: Renderiza todos os componentes
- `GetComponents()`: Retorna a lista de componentes

### Component (Classe Base Abstrata)

A classe `Component` é a base para todos os componentes do sistema.

**Responsabilidades:**
- Definir a interface comum para todos os componentes
- Manter referência ao GameObject associado
- Fornecer métodos virtuais para Start(), Update() e Render()

**Métodos virtuais:**
- `Start()`: Inicialização do componente
- `Update(float dt)`: Atualização lógica
- `Render()`: Renderização (se aplicável)

### SpriteRenderer

O componente `SpriteRenderer` é responsável exclusivamente pela renderização de sprites.

**Responsabilidades:**
- Gerenciar um objeto Sprite
- Renderizar o sprite na posição do GameObject associado
- Não controla animação (delegado ao Animator)

**Atributos principais:**
- `sprite`: Objeto Sprite que será renderizado

**Métodos principais:**
- `Render()`: Desenha o sprite na tela

### Sprite

A classe `Sprite` gerencia o carregamento e renderização de imagens, incluindo suporte a sprite sheets.

**Responsabilidades:**
- Carregar imagens de arquivos
- Gerenciar sprite sheets (múltiplos frames em uma única imagem)
- Selecionar e renderizar frames específicos
- Calcular automaticamente o clipping de frames

**Atributos principais:**
- `texture`: Textura SDL carregada na GPU
- `frameCountW`, `frameCountH`: Quantidade de frames horizontal e vertical
- `currentFrame`: Frame atual selecionado
- `clipRect`: Área de recorte para o frame atual

**Métodos principais:**
- `Open(const std::string& file)`: Carrega uma imagem
- `SetFrameCount(int frameCountW, int frameCountH)`: Define quantidade de frames
- `SetFrame(int frame)`: Seleciona um frame específico
- `Render(int x, int y)`: Renderiza o frame atual
- `GetWidth()` / `GetHeight()`: Retornam dimensões do frame

### Animation

A classe `Animation` representa os dados de uma animação.

**Responsabilidades:**
- Armazenar o intervalo de frames de uma animação
- Definir o tempo de duração de cada frame

**Atributos:**
- `frameStart`: Primeiro frame da animação
- `frameEnd`: Último frame da animação
- `frameTime`: Tempo (em segundos) de cada frame

### Animator

O componente `Animator` gerencia animações baseadas em tempo.

**Responsabilidades:**
- Armazenar múltiplas animações nomeadas
- Controlar a troca automática de frames baseada em delta time
- Atualizar o frame do SpriteRenderer associado
- Permitir troca entre diferentes animações

**Atributos principais:**
- `animations`: Mapa de animações nomeadas
- `currentAnimation`: Animação atualmente ativa
- `timeElapsed`: Tempo acumulado desde a última troca de frame
- `currentFrame`: Frame atual da animação

**Métodos principais:**
- `AddAnimation(const std::string& name, Animation animation)`: Adiciona uma animação
- `SetAnimation(const std::string& name)`: Ativa uma animação
- `Update(float dt)`: Atualiza o tempo e troca frames quando necessário

### Zombie

O componente `Zombie` representa a lógica do inimigo.

**Responsabilidades:**
- Implementar comportamento específico do zombie
- Não realiza renderização (delegado ao SpriteRenderer)
- Não controla animação (delegado ao Animator)

**Atributos principais:**
- `lifeTime`: Tempo de vida do zombie
- `sprite`: Referência ao SpriteRenderer (para futuras interações)

**Métodos principais:**
- `Update(float dt)`: Atualiza a lógica do zombie

### Classes Auxiliares

**Vec2:**
- Representa um vetor 2D (x, y)
- Utilizado para posições, velocidades e direções

**Rect:**
- Representa um retângulo (x, y, w, h)
- Utilizado para posição e dimensões de GameObjects
- Base para futuras implementações de colisão

## Como Compilar e Executar

### Pré-requisitos

Certifique-se de ter instalado:
- Xcode Command Line Tools
- SDL2, SDL2_image e SDL2_mixer (via Homebrew)

```bash
brew install sdl2 sdl2_image sdl2_mixer
```

### Compilação

No terminal, navegue até o diretório do projeto e execute:

```bash
clang++ -std=c++11 -Iinclude \
    src/*.cpp \
    -F/Library/Frameworks \
    -framework SDL2 \
    -framework SDL2_image \
    -framework SDL2_mixer \
    -o jogo
```

### Execução

Após a compilação bem-sucedida, execute:

```bash
./jogo
```

O programa abrirá uma janela de 1200x900 pixels exibindo:
- Plano de fundo renderizado
- Inimigo (zombie) com animação automática de sprites
- Música de fundo em loop

Para encerrar o programa, clique no botão de fechar da janela ou pressione Command+Q (macOS).

## Observações Finais

Esta segunda entrega estabelece a **arquitetura fundamental** do projeto através do sistema de GameObjects e Components. O foco está na separação de responsabilidades e na criação de uma base extensível.

### Características Implementadas

- Sistema de composição de componentes funcional
- Animação automática baseada em delta time
- Separação clara entre lógica, renderização e animação
- Arquitetura preparada para expansão

### Limitações Intencionais

Esta entrega **não implementa**:
- Sistema de entrada (teclado/mouse)
- Detecção de colisões
- Gameplay interativo
- Múltiplos estados de jogo
- Sistema de partículas ou efeitos visuais

Estes elementos serão desenvolvidos nas próximas entregas, utilizando a arquitetura estabelecida como fundação. A estrutura atual foi projetada para facilitar a adição de:
- Componentes de input (InputComponent)
- Componentes de física (RigidBody, Collider)
- Novos tipos de entidades (Player, Projectile, etc.)
- Sistema de estados (TitleState, GameState, EndState)
- E outros elementos que serão incorporados ao longo da disciplina

A arquitetura baseada em composição permite adicionar funcionalidades sem modificar código existente, seguindo o princípio Open/Closed do SOLID.
