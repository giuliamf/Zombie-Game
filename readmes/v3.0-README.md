## Descrição do Projeto

Esta terceira entrega expande a arquitetura construída nas entregas anteriores com a implementação de um sistema de TileSet e TileMap para renderização de mapas baseados em grade. O projeto mantém a organização orientada a objetos e o modelo baseado em composição, adicionando suporte à leitura de mapas a partir de arquivo e à seleção de tiles em um sprite sheet.

O programa exibe uma janela de 1200x900 pixels com música de fundo, plano de fundo, um inimigo animado e um mapa carregado de [`Resources/map/map.txt`](Resources/map/map.txt), renderizado a partir do tileset [`Resources/img/Tileset.png`](Resources/img/Tileset.png). Cada tile possui dimensão de 64x64 pixels, e o mapa é posicionado com origem em `(0,0)`.

## Arquitetura e Principais Classes

### Evolução da Arquitetura

A Entrega 3 mantém a arquitetura baseada em composição introduzida na Entrega 2 e adiciona um sistema específico para mapas em grade. O mapa é representado por um [`GameObject`](include/GameObject.h) que recebe um componente [`TileMap`](include/TileMap.h), enquanto o conjunto de tiles é gerenciado por uma instância de [`TileSet`](include/TileSet.h) mantida por [`State`](include/State.h).

### Game

A classe [`Game`](include/Game.h) continua responsável pelo controle da aplicação.

**Responsabilidades:**
- Inicializar e finalizar SDL2 e bibliotecas auxiliares
- Criar a janela e o renderer
- Executar o game loop principal
- Calcular delta time
- Fornecer acesso global à instância única

### State

A classe [`State`](include/State.h) passou a integrar o sistema de mapas à cena principal.

**Responsabilidades nesta entrega:**
- Criar e armazenar o [`TileSet`](include/TileSet.h)
- Instanciar o objeto do mapa
- Adicionar o componente [`TileMap`](include/TileMap.h) ao objeto correspondente
- Manter o plano de fundo, o inimigo animado e o mapa na mesma cena

**Detalhes relevantes:**
- O [`TileSet`](include/TileSet.h) é criado com tiles `64x64`
- O mapa é carregado a partir de [`Resources/map/map.txt`](Resources/map/map.txt)
- A posição inicial do mapa é `(0,0)`

### TileSet

A classe [`TileSet`](include/TileSet.h) encapsula o gerenciamento do sprite sheet de tiles.

**Responsabilidades:**
- Carregar a imagem do tileset
- Calcular o número de colunas e linhas do sprite sheet
- Configurar a quantidade de frames do sprite através de [`Sprite::SetFrameCount()`](src/Sprite.cpp:49)
- Renderizar um tile específico através de [`Sprite::SetFrame()`](src/Sprite.cpp:56)

**Método principal:**
- [`TileSet::RenderTile()`](src/TileSet.cpp:20): Seleciona o frame correspondente ao índice do tile e renderiza na posição desejada

### TileMap

A classe [`TileMap`](include/TileMap.h) é um componente responsável por carregar e desenhar o mapa.

**Responsabilidades:**
- Ler dimensões do mapa e quantidade de camadas
- Armazenar os índices dos tiles em um vetor linear
- Renderizar o mapa completo
- Renderizar cada camada separadamente

**Métodos principais:**
- [`TileMap::Load()`](src/TileMap.cpp:19): Lê o arquivo e preenche a matriz linear de tiles
- [`TileMap::Render()`](src/TileMap.cpp:56): Itera por todas as camadas
- [`TileMap::RenderLayer()`](src/TileMap.cpp:62): Calcula a posição de cada tile e desenha usando o [`TileSet`](include/TileSet.h)

### Sprite

A classe [`Sprite`](include/Sprite.h) segue sendo a base de renderização de imagens e sprite sheets.

Nesta entrega, ela é utilizada pelo [`TileSet`](include/TileSet.h) com seleção de frames. Em vez de selecionar manualmente uma subárea da textura com clipping explícito, o fluxo atual usa:
- [`Sprite::SetFrameCount()`](src/Sprite.cpp:49)
- [`Sprite::SetFrame()`](src/Sprite.cpp:56)

Isso mantém a renderização de tiles consistente com a lógica de sprite sheets já usada no restante do projeto.

### Demais Componentes

As classes já existentes continuam ativas e integradas ao projeto:
- [`SpriteRenderer`](include/SpriteRenderer.h) para renderização de sprites comuns
- [`Animator`](include/Animator.h) e [`Animation`](include/Animation.h) para animação baseada em tempo
- [`Zombie`](include/Zombie.h) para a lógica do inimigo
- [`Music`](include/Music.h) para a música de fundo

## Funcionamento do Mapa

O arquivo [`Resources/map/map.txt`](Resources/map/map.txt) define:
- largura do mapa
- altura do mapa
- profundidade, ou seja, quantidade de camadas
- sequência de índices de tiles que serão renderizados

O componente [`TileMap`](include/TileMap.h) interpreta esses valores e os converte em posições na tela de acordo com:
- coluna × largura do tile
- linha × altura do tile

Como cada tile mede `64x64`, o posicionamento segue uma grade regular. O índice armazenado no arquivo é enviado para [`TileSet::RenderTile()`](src/TileSet.cpp:20), que seleciona o frame equivalente dentro do sprite sheet.

## Como Compilar e Executar

### Pré-requisitos

Certifique-se de ter instalado:
- Xcode Command Line Tools
- SDL2, SDL2_image e SDL2_mixer via Homebrew

```bash
brew install sdl2 sdl2_image sdl2_mixer
```

### Compilação

No terminal, navegue até o diretório do projeto e execute:

```bash
clang++ src/*.cpp \
-Iinclude \
-I/opt/homebrew/include \
-L/opt/homebrew/lib \
-lSDL2 -lSDL2_image -lSDL2_mixer \
-std=c++17 \
-o jogo
```

### Execução

Após a compilação, execute:

```bash
./jogo
```

A aplicação abrirá uma janela de 1200x900 pixels exibindo:
- plano de fundo
- inimigo animado
- música ambiente
- mapa carregado por tile map a partir de arquivo externo

Para encerrar o programa, feche a janela ou utilize o atalho padrão do sistema.

## Observações Finais

Esta terceira entrega adiciona um elemento importante para jogos 2D baseados em grade: o suporte a mapas compostos por tiles reutilizáveis. Com isso, o projeto passa a possuir uma base mais próxima de uma engine de jogos completa, permitindo expansão para cenários maiores e lógica espacial mais estruturada.

### Características Implementadas

- Sistema de [`TileSet`](include/TileSet.h) funcional
- Sistema de [`TileMap`](include/TileMap.h) integrado à cena principal
- Leitura de mapa a partir de arquivo texto
- Renderização em múltiplas camadas
- Seleção de tiles por frame em sprite sheet
- Integração com a arquitetura existente baseada em GameObjects e Components

### Próximas Possibilidades de Expansão

A arquitetura atual facilita a implementação futura de:
- colisão com tiles
- câmera para mapas maiores que a janela
- carregamento de múltiplos mapas
- objetos interativos posicionados sobre o mapa
- player controlável e navegação pelo cenário

Esta entrega consolida a transição de uma cena estática para um cenário estruturado, aproximando o projeto de uma base efetiva para desenvolvimento de gameplay.
